MODELO DE CONOCIMIENTO UBIGUIA v1.0
Principio 1 — El conocimiento es el activo principal

El activo de UBIGUIA no son los textos, ni los audios, ni los QR. El activo es el conocimiento sobre un lugar.

Todo lo demás es una representación de ese conocimiento.

Consecuencias:

Un audio puede regenerarse.
Una traducción puede rehacerse.
Un QR puede cambiar.
Un Markdown puede modificarse.

Pero el conocimiento permanece.

Por eso el Motor de Investigación nunca debería producir "archivos", sino conocimiento estructurado.

Principio 2 — El conocimiento es modular

Un POI no posee un único texto.

Posee múltiples unidades de conocimiento independientes.

Ejemplo:

POI

Identidad
Historia
Arquitectura
Patrimonio
Contexto urbano
Experiencia del visitante
Datos prácticos
Curiosidades
Bibliografía

Cada módulo puede evolucionar independientemente.

Si mañana cambian los horarios:

No se modifica la Historia.

Si aparece un nuevo dato histórico:

No se regeneran las Curiosidades.

Principio 3 — Todo conocimiento tiene trazabilidad

Cada afirmación importante debe poder responder:

¿De dónde salió?
¿Quién la incorporó?
¿Cuándo?
¿Con qué nivel de confianza?

Ejemplo:

"La Casa Curutchet fue diseñada por Le Corbusier."

Origen:
UNESCO

Fecha:
2026-08-03

Confianza:
98 %

Editor:
Motor IA

Nunca queremos información "huérfana".

Principio 4 — El conocimiento tiene ciclo de vida

El conocimiento no aparece validado automáticamente.

Debe atravesar estados.

Ejemplo:

Descubierto

↓

Investigado

↓

Borrador

↓

Revisión

↓

Validado

↓

Publicado

↓

Obsoleto

Cada bloque de conocimiento posee su propio estado.

No todo el POI.

Principio 5 — Separación entre conocimiento y presentación

El conocimiento no conoce el formato final.

Desde el mismo conocimiento podremos generar:

POI_MASTER.md
Audio
Texto resumido
Texto largo
QR
Web
Aplicación móvil
PDF
Folleto

Todos son productos derivados.

Principio 6 — El conocimiento nunca se destruye

Toda modificación genera una nueva versión.

Nunca sobrescribimos silenciosamente.

Siempre existe:

Versión anterior

↓

Nueva propuesta

↓

Comparación

↓

Aprobación

Esto permite:

auditoría;
recuperación;
aprendizaje;
comparación entre investigaciones.
Principio 7 — El conocimiento puede tener múltiples autores

Un mismo bloque puede provenir de distintas fuentes.

Ejemplo:

Historia

Versión IA

+

Corrección del historiador

+

Observación del editor

+

Actualización municipal

El conocimiento final surge de la integración de esas contribuciones.

No existe un único autor.

Principio 8 — El conocimiento es reutilizable

Una investigación nunca debe servir únicamente para un POI.

Ejemplo:

Durante la investigación de Casa Curutchet aparecen:

Le Corbusier
Movimiento Moderno
Patrimonio Mundial
Arquitectura racionalista

Esos conceptos pueden reutilizarse posteriormente en:

Museo del Automóvil.
Catedral.
Museo de Bellas Artes.
Circuito Le Corbusier.

El Motor debe pensar en construir una Base de Conocimiento, no solamente POIs.

La consecuencia para el Motor

El Motor deja de ser un "generador de textos".

Pasa a ser un adquisidor de conocimiento.

Y el Editor deja de ser un editor de Markdown.

Pasa a ser un gestor de conocimiento.

Mi única incorporación a estos ocho principios

Creo que hay un noveno principio, pero lo dejaría fuera de la versión 1.0 para no alargar la definición:

El conocimiento debe poder compartirse entre POIs.

Ese principio abre la puerta a una verdadera Base de Conocimiento UBIGUIA, donde conceptos como personas, 
estilos arquitectónicos, acontecimientos históricos o instituciones existen una sola vez y son referenciados 
por múltiples POIs. No lo implementaría ahora, pero diseñaría el Modelo de Conocimiento v1.0 de forma que esa 
evolución sea posible sin tener que rehacer la arquitectura. Esa decisión puede marcar la diferencia entre un 
editor de guías y una plataforma de conocimiento turístico.
